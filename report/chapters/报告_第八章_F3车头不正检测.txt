================================================================
    共享单车多传感器数据采集与健康检测系统

    第八章  F3 — 车头不正检测
================================================================



8.1  物理原理
================================================================

8.1.1  故障模型

车头不正（Handlebar Misalignment）是指自行车前叉与车把之间的连接
出现微小角位移，使车把的指向与车轮的滚动方向之间产生一个固定的
偏差角 Δθ。这一故障通常源于以下原因：

  · 外力撞击：单车倒地或碰撞时车把受到侧向冲击，前叉与车把立管的
    压紧螺丝产生滑移。
  · 长期疲劳：反复的转向操作导致紧固件微动松动。
  · 装配误差：出厂时车把与前轮未对准即锁紧。

骑行者在车把歪斜的单车上为了维持直线行驶，必须持续施加一个补偿
力矩。从传感器的角度看，这意味着陀螺仪 Z 轴（偏航角速度）在整车
直线前进时并非为零——它存在一个非零的时间平均偏置。本文正是通过
检测这一偏置来间接推算 Δθ。

8.1.2  信号特征

在匀速直行路段上，健康的单车陀螺仪 Z 轴读数围绕零值随机波动，其
时间均值趋近于零（仅存在传感器自身的零偏漂移，通常 < 0.5°/s）。

车头不正的单车则呈现不同的模式：为了维持直行，骑行者需要持续向
一侧施加轻微的转向力矩，导致手机绕垂直轴产生一个恒定的角速度偏置。
在 2 秒以上的观察窗口内，该偏置的方向和大小保持相对稳定。

重要的工程约束：F3 仅适用于**直行段**。转弯、变道、避让障碍物
等机动动作会产生远大于偏置的角速度变化，完全淹没微弱的偏置信号。
因此 F3 的第一步必须是自动筛选直行窗口。



8.2  算法流程（v3.2）
================================================================

F3 的当前版本号为 v3.2，该版本在基础的陀螺仪偏置检测之上新增了
加速度计辅助的侧向晃动惩罚机制。完整流程分为四个阶段。

8.2.1  第一阶段 — 直行段自动筛选

  目标：从全程陀螺仪数据中自动识别最有可能为直行的时间段。

  方法：
    ① 将陀螺仪 Z 轴数据重采样到 50 Hz 均匀网格。
    ② 以 5 秒为窗口长度、窗口长度的 1/4 为步长，计算每个窗口内
       gz 的标准差 σ_gz。
    ③ 按 σ_gz 升序排列所有窗口，取前 30% 作为「准直行段」。

  原理：直行时偏航角速度变化平缓（σ_gz 低），转弯或晃动时 σ_gz
  急剧增大。取最低 30% 而非绝对值阈值的策略避免了为不同骑行风格
  （激进/平稳）设定不同参数——无论骑行多激进，总存在相对最直的
  30% 时段。

  若最佳窗口的 σ_gz 仍超过 0.3 rad/s（约 17°/s），则判定全程
  无有效直行段，返回满分（数据不足以判断车头状态）。

8.2.2  第二阶段 — 陀螺仪偏置估计

  对每个准直行段的 gz 值取算术平均，得到该段的偏置估计值。
  取所有段的**中位数**（而非均值）作为全局 yaw_bias，以抵抗个别
  段因偶发机动而出现的极端偏置值。

  等效车头偏角 Δθ₁ 的物理含义是"在观察时间 T 内，若陀螺仪持续
  输出恒定偏置 yaw_bias，则累积偏航角为 yaw_bias × T"。

  计算公式：
    Δθ₁ = deg( |yaw_bias| × min(total_obs_time, 30) )

  其中 total_obs_time = 直行段数 × 5 秒。取 min(·,30) 的上限
  防止观察窗口过长导致 Δθ 累积到物理上不可能的值（例如陀螺仪
  零偏被错误解释为车头偏斜，积分 300 秒后 Δθ 可达数十度）。

  符号一致性增强：若各直行段 gz 均值的方向高度一致（>70% 同符号），
  且均值的绝对值 > 0.001 rad/s，则对 Δθ 施加轻度放大：
    boost = 1.0 + (sign_consistency - 0.7) × 0.3
    Δθ ×= boost。

  方向一致性是"偏置是真实的而非随机波动"的重要信号——若 10 个
  直行段的 gz 均值中有 9 个为正，该偏置显然非偶然。

8.2.3  第三阶段 — 加速度计侧向晃动惩罚（v3.2 新增）

  **动机**：当陀螺仪偏置很小（Δθ < 3°）时，不能直接断言车头一定
  正常。存在一种场景：车头轻微歪斜，但骑行者通过身体的补偿晃动
  维持了直行——这种情况下陀螺仪偏置确实很小（骑行者替代车把完成
  了补偿），但加速度计会记录到额外的身体晃动。

  **方法**：
    ① 对加速度计三轴数据分别去除重力直流偏置（全程均值）。
    ② 计算三轴去重力残差的幅度：dev = √(ax'² + ay'² + az'²)。
       （方向无关的晃动度量，不依赖手机安装方向。）
    ③ 重采样到相同时间基，与 gz 窗口对齐。
    ④ 对每个直行段计算 dev 的标准差（σ_dev）。
    ⑤ 计算稳定性比值：
         stability_ratio = median(σ_dev in straight segments)
                         / σ_dev(all data)
       健康车：直行段稳定 → ratio 低（→ 0.5）
       车头不正：直行段也需要补偿晃动 → ratio 接近 1.0

  **惩罚触发条件**（三条件同时满足）：
    · Δθ < 3°（陀螺仪未检测到明显偏置）
    · stability_ratio > 0.55（侧向晃动超出正常范围）
    · 加速度计数据可用

  **惩罚强度**：
    wn = (stability_ratio - 0.55) / (0.80 - 0.55)，限制在 [0, 1]。
    wobble_factor = wn × 2.0
    Δθ ×= (1.0 + wobble_factor)

  即最大可将 Δθ 放大至 3 倍（当 stability_ratio ≥ 0.80 时）。

  注意：wobble 惩罚的触发门限 Δθ < 3° 决定了它**仅影响陀螺仪偏置
  极小的案例**。若 Δθ 本身已较大（如 > 5°），陀螺仪已有足够证据
  判为偏斜，不再借助加速度计惩罚。

8.2.4  第四阶段 — 评分

  采用线性插值评分，阈值为 θ_ok = 4° 和 θ_bad = 10°：

    if Δθ ≤ 4°:             score = 100
    elif Δθ ≥ 10°:           score = 0
    else:                    score = 100 × (1 - (Δθ-4)/(10-4))

  阈值的工程含义：
    Δθ ≤ 4°：偏差在正常装配公差内（车把与前轮的对中度良好），满分。
    4° < Δθ < 10°：可感知的微小偏斜，分数线性衰减。
    Δθ ≥ 10°：明显的车把歪斜，骑行操控性显著下降，零分。



8.3  实验验证
================================================================

利用三组真实骑行数据对 F3 进行验证。

表 8-1  三组数据集的 F3 检测结果

  ┌──────┬──────────────┬──────────────┬──────────────┬──────────┐
  │ 数据集│ Δθ (°)       │ 直行段数      │ 评分         │ 判定      │
  ├──────┼──────────────┼──────────────┼──────────────┼──────────┤
  │ (3)  │ 3.18         │ —            │ 100.0        │ 正常      │
  │ (6)  │ 5.11         │ 13           │ 81.5         │ 轻微偏斜   │
  │ (2)  │ 4.38         │ —            │ 93.7         │ 正常      │
  └──────┴──────────────┴──────────────┴──────────────┴──────────┘

分析：

  · 数据集 (3)：Δθ=3.18° < 4°，满分。该车车把与前轮对中度极好。

  · 数据集 (6)：Δθ=5.11°，处于 4°~10° 的线性衰减区。评分 81.5
    反映该车可能存在轻微的车把偏斜——用户可能感觉"骑着有点别扭"
    但不会强烈意识到故障。13 个直行段提供了足够的统计样本量，
    偏置估计的置信度较高。

  · 数据集 (2)：Δθ=4.38°，恰好略超 4° 线。评分 93.7 表示极其
    轻微的偏斜，基本可视为正常范围。

需要指出的是，手机在车把支架上的安装角度偏差（±1~3°）会被 F3 解读
为车头偏斜。实际部署中建议在每次安装手机后进行一次基准标定——沿
已知直线骑行 10 秒记录 gz 均值作为"零偏基准"，后续检测值减去该
基准后再评分。



8.4  陀螺仪 Z 轴零偏的物理本质
================================================================

MEMS 陀螺仪在零角速度输入时，理想输出为 0 rad/s。但实际上器件存在
固有零偏（Zero-Rate Offset），且该零偏随温度和供电电压缓慢漂移。

F3 利用的不是绝对零偏值，而是**直行段相对于全程的相对偏置**。
算法不依赖陀螺仪的出厂标定精度，只要求零偏在十几秒的直行窗口内
保持稳定——这一条件在骑行场景下是满足的（手机温度变化速率远低于
陀螺仪零偏的温漂时间常数）。

这一点解释了为什么 F3 可以在各种型号的手机上工作，无需逐设备标定：
设备间差异体现为零偏的绝对值不同，但本算法需要的是同一设备在同一次
骑行的直行段相对于转弯段的"模式差异"，而非跨设备的绝对值。



8.5  本章小结
================================================================

  (1) F3 通过陀螺仪 Z 轴偏置在直行段中的非零均值来推断车把偏角。
      5 秒滑动窗口 + 前 30% 最低方差的策略无需设定绝对阈值即可
      自适应不同骑行风格。

  (2) v3.2 新增的加速度计侧向晃动惩罚利用了人体补偿晃动的物理特性，
      在陀螺仪偏置微小但骑行者身体不稳定的场景中捕获隐性偏斜。

  (3) 评分采用 4°~10° 的线性插值，正常装配公差内满分，明显偏斜
      零分。符号一致性增强和 wobble 惩罚各自只作用于特定子集
      （前者需要方向高度一致，后者仅在 Δθ < 3° 时触发），避免
      了对全局数据施加无差别修正。

  (4) 三组数据的验证表明 F3 能够有效区分对中度良好（Δθ < 4°, 100
      分）与存在微小偏斜（Δθ 5°左右, 80~95 分）的单车。
