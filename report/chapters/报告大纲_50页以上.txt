第一章  绪论（预计 5~6 页）
================================================================

1.1  项目背景与意义
     - 共享单车行业现状：运维成本痛点（坏车巡检靠人工，效率低）
     - 「软故障」定义：轮胎微偏摆、链条干磨异响、车把歪斜——骑行者不易察觉但影响安全
     - 本项目的价值定位：自动化的、可量化的、低成本的快速检测方案

1.2  国内外研究现状
     - 传统自行车检测：人工目视 + 经验判断
     - 工业振动分析：轴承故障诊断（包络谱、倒谱）
     - 车载诊断系统 (OBD) 在汽车领域的借鉴
     - 手机传感器在交通领域的应用趋势
     - 现有方案的不足与本文的切入点

1.3  项目目标与核心指标
     - 采集端目标：Android手机多传感器同步采集（100Hz加速度计+50Hz陀螺仪+10Hz GPS+8kHz音频）
     - 检测端目标：三级故障检测（F1轮胎偏摆 / F2链条异响 / F3车头不正）
     - 输出目标：0~100综合健康评分 + 骑行建议（推荐/谨慎/换车）
     - 性能指标：实时采集不丢数据、算法全量分析<30s

1.4  论文组织结构
     - 第二章 系统总体设计
     - 第三章 Android多传感器数据采集子系统

第三章  Android多传感器数据采集子系统（预计 7~8 页）
================================================================

3.1  系统需求分析
     - 功能需求：同步采集4类传感器、前台服务保活、数据持久化
     - 非功能需求：不丢数据、低功耗（Partial WakeLock）、竖屏锁定

3.2  权限体系设计
     - 关键权限：ACCESS_FINE_LOCATION（GPS）、RECORD_AUDIO（麦克风）
     - 辅助权限：ACCESS_COARSE_LOCATION、POST_NOTIFICATIONS
     - 存储权限：Android 11+ MANAGE_EXTERNAL_STORAGE 全局文件访问
     - 权限申请流程：关键权限 → 存储权限 → 启动采集（分步请求）

3.3  前台服务架构（SensorService）
     - 为什么需要前台服务：Android 8.0+ 后台限制，必须前台+通知保活
     - START_STICKY 策略：被杀后自动重启
     - 通知渠道设计：IMPORTANCE_LOW + 持续通知
     - 前台服务类型声明：location|microphone (Android 14+ 强制)
     - 生命周期管理：onCreate → onStartCommand → onDestroy 完整状态机

3.4  多传感器采集器详细设计

 3.4.1  加速度计采集器（AccelCollector）
        - 传感器类型：TYPE_ACCELEROMETER
        - 采样率：SENSOR_DELAY_GAME (100Hz)
        - 输出字段：timestamp_ns, ax, ay, az
        - 数据格式：CSV行写入，线程安全（synchronized）

 3.4.2  陀螺仪采集器（GyroCollector）
        - 传感器类型：TYPE_GYROSCOPE
        - 采样率：20000μs (50Hz)
        - 输出字段：timestamp_ns, gx, gy, gz（Z轴为偏航角速度）
        - 数据格式：CSV行写入，线程安全

 3.4.3  GPS采集器（GpsCollector）
        - 双源定位：GPS_PROVIDER (10Hz) + NETWORK_PROVIDER (5s备用)
        - LocationListener 回调 → elapsedRealtimeNanos 时间戳
        - 速度与航向角：location.speed + location.bearing
        - 容错处理：hasSpeed/hasBearing 判断，无值时留空

 3.4.4  音频采集器（AudioCollector）
        - AudioRecord API：8kHz采样率，16-bit PCM，单声道
        - 缓冲区设计：minBufSize × 2
        - 双文件输出：音频.pcm（原始PCM）+ 音频_时间戳.csv（时间戳→采样索引映射）
        - 独立协程：Dispatchers.IO 读写循环

3.5  数据同步与写入机制
     - 统一时间基准：SystemClock.elapsedRealtimeNanos()（单调时钟，不受系统时间跳变影响）
     - 合并文件设计：「传感器数据.txt」统一CSV，每行一条传感器记录
     - CSV列结构：timestamp_ns, 类型标签, ax,ay,az, lat,lon,speed,course, gx,gy,gz
     - 线程安全：每种采集器独立写入同一Writer（synchronized锁）

3.6  WakeLock 休眠控制
     - PARTIAL_WAKE_LOCK：CPU保持运行，屏幕可熄灭
     - 超时保护：10分钟自动释放

3.7  文件存储路径设计
     - 优先路径：Documents/自行车数据/yyyyMMdd_HHmmss/
     - 回退路径：应用私有目录（getExternalFilesDir）
     - 每会话独立文件夹：传感器数据.txt + 音频.pcm + 音频_时间戳.csv

3.8  崩溃恢复机制
     - UncaughtExceptionHandler → SharedPreferences 存储崩溃日志
     - 下次启动显示 CrashScreen → 用户可关闭继续使用

第六章  F1 轮胎偏摆检测（预计 5~6 页）
================================================================

6.1  物理原理
     - 轮胎偏摆的振动特征：车轮每转一圈在变形处产生周期性冲击
     - 正常轮胎：振动随机，FFT频谱平坦
     - 偏摆轮胎：在轮频 f 出现显著峰值，倍频 2f 处有谐波响应
     - 关键公式：f = v / (2πr)，r=0.35m

6.2  算法流程（6步）
     Step 1: Z轴加速度去直流 → 消除重力分量
     Step 2: 重采样100Hz + Butterworth带通滤波 2~40Hz
     Step 3: 滑动窗口平整路面判定（1s窗，方差<0.5=平整）
     Step 4: 车轮转频估计（GPS先验±2Hz优先，降级全范围扫描）
     Step 5: FFT归一化幅值提取 f 与 2f 处幅值 A1, A2
     Step 6: P = A1 + 0.5×A2 → 线性插值评分 → 置信度加权

6.3  GPS速度先验优化（v4.0）
     - 优先选「最接近期望频率的峰」而非「最强峰」
     - 避免路面颠簸共振误判为轮频

6.4  阈值标定
     - P_healthy = 0.15（正常轮胎随机激励基准）
     - P_severe = 0.60（严重偏摆判别阈值）
     - 置信度修正: score *= (0.7 + 0.3 × flat_fraction)

6.5  代码实现要点
     - estimate_wheel_frequency() 双模式设计
     - amplitude_at() 频率容差±0.3Hz的最大幅值搜索

第七章  F2 链条异响检测（预计 7~8 页）★最复杂的算法★
================================================================

7.1  核心问题：区分链条异响 vs 环境噪音
     - 链条异响 = 与踏频同步的周期性金属冲击声
     - 环境噪音 = 风噪/车流/人声，无周期性特征
     - 为什么传统方法（MFCC+SVM）不够：需要标注数据，且MFCC无法区分周期性来源

7.2  包络谱分析理论基础
     - 希尔伯特变换定义与性质
     - 解析信号与包络的数学推导
     - 包络谱：对包络做FFT，反映「幅值调制的频率成分」
     - 物理直觉：链条每转一圈冲击一次 → 包络在踏频处有强周期分量

7.3  Cepstrum（倒谱）理论基础
     - Cepstrum = |IFFT(log|FFT(x)|)|²
     - Quefrency（倒频率）与周期的对应关系
     - 对周期性冲击的敏感度：优于直接FFT
     - 双通道验证的必要性：包络谱+Cepstrum独立验证，降低误报

7.4  算法流程（12步）
     Step 1:  采样率估计 → 重采样8kHz
     Step 2:  踏频估计——自相关法（无轮频输入时自动估算）
     Step 3:  带通滤波 2~4kHz（链条共振频带）
     Step 4:  希尔伯特变换提取包络
     Step 5:  包络低通滤波 0~10Hz
     Step 6:  包络谱 SNR @ 踏频（核心特征①）
     Step 7:  谐波检测——2次/3次谐波存在比例（核心特征②）
     Step 8:  冲击相位一致性——圆形方差分析（核心特征③）
     Step 9:  Cepstrum周期性冲击得分（核心特征④）
     Step 10: 辅助特征——高频能量比 + 峰值因子
     Step 11: 异常得分融合——四核心+两辅助加权
     Step 12: 决策与评分——异常得分→分类+置信度→0~100分

7.5  特征权重设计原理
     - 核心通道权重0.60：envelope_score（0.35×SNR + 0.25×谐波 + 0.20×相位 + 0.20×cepstrum）
     - 辅助通道权重0.40：高频能量比0.55 + 峰值因子0.45
     - 设计原理：核心特征判断「是否为链条特有的周期冲击」，辅助特征提供额外敏感度

7.6  版本演进（v1.0 → v3.0）
     - v1.0: FFT频谱+能量包络（无法区分噪音）
     - v2.0: MFCC+SVM代理（需训练数据，特征解释性弱）
     - v3.0: 包络谱+Cepstrum（零训练数据，可解释性强）

第八章  F3 车头不正检测（预计 5~6 页）
================================================================

8.1  物理原理
     - 车头偏斜 → 骑手身体朝向与车身前进方向存在固定夹角
     - IMU偏航角变化 vs GPS航向角变化 → 系统性偏差 Δθ
     - 检测前提：直行段（排除转弯干扰）

8.2  GPS增强模式（推荐，有GPS数据时）
     Step 1: 骑行状态判定——速度≥2m/s 且 航向变化率<5°/s
     Step 2: 3点中值滤波平滑GPS航向角
     Step 3: 取最长连续直行段（groupby连续分组）
     Step 4: 在直行段时间范围内积分IMU偏航角
     Step 5: GPS航向变化 vs IMU偏航变化 → median偏差 Δθ
     Step 6: 环绕处理（0°/360°越界）
     Step 7: 线性插值评分——Δθ≤5°→100 / ≥15°→0

8.3  IMU降级模式（无GPS数据时自动启用）
     - 滑动窗口gz方差最小30%窗口 → 「准直行段」
     - gz偏置估计 + 偏航角积分偏差
     - Δθ = 0.7×偏置项 + 0.3×积分项

8.4  模式切换逻辑
     - GPS数据≥3条 → 优先GPS模式
     - GPS模式失败（无直行段/速度不足/段太短）→ 降级IMU模式
     - IMU降级无有效直行段 → 返回满分（数据不足以判断）

8.5  设计文档vs代码实现差异分析
     - 航向变化率阈值从3°/s放宽到5°/s（适配1Hz GPS噪声）
     - 中值滤波从无到有（GPS噪声抑制）
     - 最小值惩罚的精细调整

第九章  综合健康评分机制（预计 4~5 页）
================================================================

9.1  「木桶效应」设计哲学
     - 问题：算术平均会掩盖单项严重故障
       - 例：F1=0, F2=100, F3=100 → 算术平均=67（还能骑?）
     - 解决方案：调和平均 + 最小值惩罚

9.2  数学公式
     Step 1: 加权调和平均 H = 1 / (0.40/F1 + 0.30/F2 + 0.30/F3)
     Step 2: 最小值惩罚因子 penalty = min(F1,F2,F3) / 100
     Step 3: 最终评分 S = H × penalty

9.3  权重设计原理
     - F1 (0.40) > F2 (0.30) = F3 (0.30)
     - 轮胎偏摆直接影响骑行安全（爆胎风险），权重最高
     - 链条异响和车头不正同等重要

9.4  分级决策规则
     - S ≥ 70 →「推荐骑行」(good)
     - 50 ≤ S < 70 →「谨慎使用」(caution)
     - S < 50 →「建议换车」(bad)

9.5  评分特性分析
     - 单调性：任一子分下降 → 总分下降
     - 敏感性：低分区变化比高分区更敏感（调和平均特性）
     - 边界行为：全100→100, 任一0→≈0
     - 举例：F1=80,F2=70,F3=60 → H≈68.6, penalty=0.6 → S≈41
