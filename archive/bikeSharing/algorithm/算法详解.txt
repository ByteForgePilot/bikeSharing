================================================================
  共享单车健康快速检测系统 — 算法详解 (v4.0)
================================================================

【系统概述】

本系统通过分析骑行过程中采集的传感器数据（IMU加速度计、陀螺仪、GPS）
和音频数据，对共享单车的三大关键部件进行健康检测，最终输出一个 0~100
的综合评分，并给出骑行建议。

核心设计理念：「木桶效应」—— 任何一项严重故障都不会被其他高分项掩盖。


================================================================

================================================================
二、数据结构定义
================================================================

AccelSample  ─ 加速度计单次采样
  ├─ timestamp_ns : 纳秒时间戳
  ├─ ax, ay, az   : X/Y/Z 三轴加速度 (m/s²)，Z轴朝上

GyroSample   ─ 陀螺仪单次采样
  ├─ timestamp_ns : 纳秒时间戳
  ├─ gx, gy, gz   : 三轴角速度 (rad/s)，Z轴为偏航轴

GpsSample    ─ GPS 单次定位
  ├─ timestamp_ns : 纳秒时间戳
  ├─ lat, lon     : 经纬度
  ├─ speed_ms     : 地面速度 (m/s)
  └─ course_deg   : 航向角 (度, 0~360, 北为0)

AudioChunk   ─ 音频块时间戳映射
  ├─ timestamp_ns      : 本块起始时间戳
  └─ cumulative_samples: 累计采样点数（用于定位 PCM 数据）

物理常量:  WHEEL_RADIUS = 0.35m  (共享单车标准轮胎半径)

三、数据加载 (load_sensor_data / load_audio / load_audio_timestamps)
================================================================

1. 传感器数据解析 (load_sensor_data)
   - 输入格式：CSV，首行为表头
   - 每行格式：timestamp, 类型标签, ax,ay,az, lat,lon,speed,course, gx,gy,gz
   - 自动兼容 v2 (无GPS) 和 v4 (有GPS) 两种格式
   - 按类型标签（加速度计/陀螺仪/GPS）分流到对应列表

2. 音频数据加载 (load_audio)
   - PCM 16-bit 小端格式 → float32 归一化到 [-1, 1]

3. 音频时间戳加载 (load_audio_timestamps)
   - CSV 格式：时间戳, 累计采样数 → AudioChunk 列表

四、大数据自适应窗口选取 (select_analysis_window)  ★关键创新★
================================================================

【目的】当输入数据超过 30 秒时，不是简单地截取开头，而是智能选取
       「骑行质量最高」的 15 秒窗口进行分析。

【判定阈值】
  MAX_DURATION_S    = 30s    (传感器或音频任一项超过即触发)
  WINDOW_DURATION_S = 15s    (选取的窗口长度，可环境变量覆盖)

【算法步骤】

  第1步: 重采样加速度计 Z 轴和陀螺仪 Z 轴到统一 50Hz 网格

  第2步: 用滑动窗口一次性计算所有候选窗口的评分向量:

          scores = az_var × 1.0          ← 路面越平 (Z轴方差越低) 越好
                 + gz_var × 10.0         ← 骑得越直 (偏航变化越小) 越好
                 + speed_var × 5.0        ← 速度越稳 (匀速) 越好

          三项都是「越低越好」——取 argmin 即为最佳窗口。

  第3步: 按最佳窗口的起止时间戳裁剪:
         - 传感器数据: 时间戳过滤
         - 音频数据: 通过 cumulative_samples 映射裁剪 PCM 数组
         - GPS 数据: 时间戳过滤

【返回值】
  {
    used_window:    是否触发了窗口选取
    accel_slice:    裁剪后的加速度计列表
    gyro_slice:     裁剪后的陀螺仪列表
    audio_slice:    裁剪后的音频 numpy 数组
    audio_ts_slice: 裁剪后的音频时间戳列表
  }


================================================================
五、F1 — 轮胎偏摆检测 (detect_tire_wobble)  权重 0.40
================================================================

【物理原理】
轮胎偏摆（轮圈变形/辐条松动）会使车轮每转一圈产生一次周期性振动。
正常车轮: 振动随机，幅值小。
偏摆车轮: 在轮频 f 处出现显著周期振动峰，且在 2f (倍频) 处也有响应。

【算法流程】

  Step 1: 去直流 → Z轴加速度减去均值（消除重力分量）

  Step 2: 重采样到 100Hz，Butterworth 带通滤波 2~40Hz
          (低频去除身体晃动，高频去除传感器噪声)

  Step 3: 平整路面判定
          对滤波后信号做 1秒滑动窗口方差计算
          方差 < 0.5 的窗口标记为「平整路面」
          计算平整路面占比 flat_fraction (0~1)

          若 flat_fraction ≥ 20%，只用平整段做 FFT
          若不足 20%，用全部数据（路面干扰较大，后续会降权）

  Step 4: 车轮转频估计 (estimate_wheel_frequency)
          ┌─ 有 GPS 车速时 ────────────────────────────┐
          │ f_expected = v / (2π × 0.35)               │
          │ 在 f_expected ± 2Hz 范围内搜索 FFT 峰值     │
          │ 选「最接近期望频率的峰」而非最强峰          │
          │ (最强峰可能是路面颠簸共振或倍频，非轮频)    │
          └────────────────────────────────────────────┘
          ┌─ 无 GPS 时 ────────────────────────────────┐
          │ 在 1.5~8Hz 范围内选 FFT 最强峰             │
          │ (对应车速 6~30 km/h)                        │
          └────────────────────────────────────────────┘

  Step 5: FFT → 提取幅值
          归一化 FFT 幅值: mag = |FFT(x)| / (n/2)
          取 f_wheel 附近 ±0.3Hz 的最大幅值 → A1
          取 2×f_wheel 附近 ±0.3Hz 的最大幅值 → A2

  Step 6: 计算偏摆特征值 P = A1 + 0.5×A2

          P 的物理含义:
          - A1: 轮频处振动 (每转一圈冲击一次)
          - 0.5×A2: 倍频处振动 (每转一圈冲击两次，权重减半)
          - P 越大 → 轮胎周期性振动越强 → 偏摆越严重

  Step 7: 线性插值评分
          P ≤ 0.15  →  score = 100  (正常轮胎，仅路面随机激励)
          P ≥ 0.60  →  score = 0    (严重偏摆)
          中间值    →  score = 100 × (1 - (P-0.15)/(0.60-0.15))

  Step 8: 置信度加权
          confidence = 0.7 + 0.3 × flat_fraction
          (平整路面占比越低 → 置信度越低 → 分数下修)
          final_score = score × confidence

【输出】
  score, wheel_freq_hz, amplitude_f, amplitude_2f, P_value, flat_fraction

六、F2 — 链条异响检测 (detect_chain_noise)  权重 0.30
================================================================

【物理原理】★★★ 本系统最精密的算法 ★★★
链条异响 = 与踏频同步的周期性金属冲击声。
关键区分: 链条异响有「稳定的踏频周期」，环境噪音（风噪/车流/人声）则无。

【核心方法】包络谱分析 (Envelope Spectrum) + Cepstrum 双通道检测
根本不需要训练数据 —— 纯信号处理。

【算法流程】共 12 个步骤：

  Step 1 — 采样率估计
          从音频时间戳计算原始采样率: fs = Δsamples / Δt
          防御性限制在 1000~96000 Hz 范围内
          重采样到 8000 Hz (链条冲击分析不需要高频)

  Step 2 — 踏频估计 (无 GPS 轮频时自动估算)
          ① 希尔伯特变换 → 包络信号
          ② 低通滤波 0~10Hz → 自相关找基频延迟
          ③ 在 0.2~1.0s 延迟范围 (对应 1~5Hz 踏频) 找峰值
          ④ 防御性限制在 0.5~8 Hz 合理范围

  Step 3 — 带通滤波 2000~4000 Hz
          链条金属冲击的共振频带集中在此范围
          滤除低频人体动作、风噪和高频电子噪声

  Step 4 — 希尔伯特包络提取
          对滤波后信号做 Hilbert 变换 → |analytic_signal|
          包络 = 高频振动的「轮廓线」，反映冲击的节奏模式

  Step 5 — 包络低通滤波
          低通 0~10Hz，仅保留踏频及其低次谐波范围的包络变化

  Step 6 — 包络谱 SNR @ 踏频 (★核心特征★)
          对低通包络做 FFT → 包络谱
          计算踏频处峰值 vs 噪声基底的 SNR (dB)
          SNR>8dB → 强烈的踏频周期调制 → 链条异响
          SNR<3dB → 无明显周期调制 → 正常/环境噪音

  Step 7 — 谐波检测 (★核心特征★)
          检查包络谱中是否存在踏频的 2次/3次谐波
          检测到的谐波比例 = 检测数/3
          链条异响因金属非线性冲击，通常产生丰富谐波

  Step 8 — 冲击相位一致性 (★核心特征★)
          原理: 链条异响的冲击在曲柄固定相位发生
                → 包络峰值间隔应锁定在踏频周期的整数倍
          方法:
          ① find_peaks 找到包络的各个峰值
          ② 计算峰-峰间隔 → 映射到等效曲柄相位
          ③ 圆形方差 (Circular Variance) 衡量相位集中度
             R≈1 → 所有冲击对齐同一相位 → 链条特征
             R≈0 → 冲击随机分布 → 环境噪音

  Step 9 — Cepstrum 周期性冲击检测 (★核心特征★)
          Cepstrum = |IFFT(log|FFT(x)|)|²
          对周期性冲击极其敏感 ——
          链条异响的规则金属撞击在 cepstrum 中产生清晰峰值
          风噪/人声等非周期信号无此特征

          方法: 在目标 quefrency (1/踏频) 处计算 SNR
                SNR≥8 → cepstrum_score=1 (异常)
                SNR≤2 → cepstrum_score=0 (正常)

  Step 10 — 辅助特征
           高频能量比: 2~4kHz 能量 / 全频带能量
           (链条冲击能量集中在高频)
           峰值因子: max(|x|) / RMS
           (冲击信号峰值因子高，连续噪音低)

  Step 11 — 异常得分融合
           核心得分 (权重 0.60):
             envelope_score = 0.35×snr_score + 0.25×harm_score
                            + 0.20×phase_score + 0.20×cepstrum_score

           辅助得分 (权重 0.40):
             auxiliary_score = 0.55×hf_score + 0.45×crest_score

           综合异常得分:
             anomaly_score = 0.60×envelope_score + 0.40×auxiliary_score

  Step 12 — 决策与评分
            anomaly < 0.25  →  正常, confidence ≥ 0.8
            anomaly > 0.55  →  异响, confidence ≥ 0.8
            居中模糊区      →  按置信度线性插值，confidence 自动降到 0.5~0.8
            最终评分: 正常+高置信 → 100, 异响+高置信 → 0, 模糊区 → 线性

【输出】
  score, prediction, confidence, pedal_snr_db, harmonic_ratio,
  phase_consistency, cepstrum_score, hf_energy_ratio, anomaly_score


================================================================
七、F3 — 车头不正检测 (detect_handlebar_misalignment)  权重 0.30
================================================================

【物理原理】
车头偏斜 → IMU 测量的偏航角变化与 GPS 航向角变化存在系统性偏差 Δθ。
正常车头: 两者近乎 1:1 对应。
偏斜车头: 骑手身体朝向与车身前进方向不一致，产生固定偏差。

【两种模式】

┌─────────────────────────────────────────────────────────┐
│ GPS 增强模式 (_detect_handlebar_with_gps)               │
│                                                         │
│ Step 1 — 骑行状态判定:                                   │
│   条件: GPS速度 ≥ 2m/s  AND  航向变化率 < 5°/s           │
│   (航向角先用 3 点中值滤波平滑 GPS 1Hz 噪声)              │
│                                                         │
│ Step 2 — 取最长连续直行段:                               │
│   将满足条件的 GPS 点按连续性分组                        │
│   取最长的一段 (至少 2 秒)                               │
│                                                         │
│ Step 3 — 积分 IMU 偏航角:                                │
│   在直行段时间范围内，积分陀螺仪 gz:                      │
│     yaw_delta = cumsum(gz × dt)  →  转为角度             │
│                                                         │
│ Step 4 — 对比 GPS 航向 vs IMU 偏航:                      │
│   将 GPS 航向角插值到 IMU 时间轴                         │
│   计算偏差序列: deviation = |GPS_course_change - IMU_yaw_change|│
│   取中位偏差 Δθ (比均值更抗噪声)                          │
│                                                         │
│ Step 5 — 线性评分:                                       │
│   Δθ ≤ 5°   → score = 100 (正常)                        │
│   Δθ ≥ 15°  → score = 0   (严重偏斜)                    │
│   中间值    → score = 100×(1-(Δθ-5)/(15-5))             │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ IMU 降级模式 (_detect_handlebar_imu_only)                │
│ (当没有 GPS 数据时自动启用)                               │
│                                                         │
│ Step 1 — 滑动窗口方差分析:                               │
│   gz 重采样到 50Hz，5秒滑动窗口                          │
│   选 gz_std 最小的 30% 窗口作为「准直行段」               │
│   若最佳窗口 gz_std > 0.3 → 无有效直行段，返回100分       │
│                                                         │
│ Step 2 — 偏置估计:                                       │
│   对最佳窗口计算 gz 均值 (偏航角速率偏置)                 │
│   积分偏航角偏差: cumsum(gz) × dt                        │
│                                                         │
│ Step 3 — 偏差合成:                                       │
│   Δθ_from_bias = |gz_mean| × 2s (2秒观测窗口)           │
│   Δθ_from_yaw  = mean(|yaw_deviation|)                  │
│   Δθ = 0.7×Δθ_from_bias + 0.3×Δθ_from_yaw              │
│                                                         │
│ Step 4 — 评分: 与 GPS 模式使用相同的阈值                  │
└─────────────────────────────────────────────────────────┘

【输出】
  score, delta_theta_deg, yaw_bias_rad_s, straight_segments, method


================================================================
八、综合健康评分 (compute_health_score) — 「木桶效应」
================================================================

【目的】防止某项严重故障被其他高分项「平均掉」。
        例如：轮胎偏摆严重(0分) + 链条正常(100分) + 车头正常(100分)
        算术平均 = 67 分（还能骑?）→ 不合理！
        木桶效应 → 接近 0 分（不能骑）→ 合理。

【公式】

  Step 1: 加权调和平均 H
          1/H = 0.40/F1 + 0.30/F2 + 0.30/F3

          调和平均的特性: 对低分值极其敏感。
          当任一项趋近 0 时，H 也趋近 0。

  Step 2: 最小值惩罚因子
          penalty = min(F1, F2, F3) / 100

          最差的一项直接决定上限。
          若 min=100，penalty=1.0 (无惩罚)
          若 min=0，  penalty=0   (直接归零)

  Step 3: 最终评分
          S = H × penalty

  Step 4: 分级建议
          S ≥ 70  →  level="good"     → 「推荐骑行」
          50≤S<70 →  level="caution"  → 「谨慎使用」
          S < 50  →  level="bad"      → 「建议换车」

【示例】
  F1=100, F2=100, F3=100  →  H=100,  penalty=1.0, S=100  [完美]
  F1=0,   F2=100, F3=100  →  H≈0,    penalty=0,   S≈0    [一票否决]
  F1=80,  F2=70,  F3=60   →  H≈68.6, penalty=0.6, S≈41.2 [谨慎]
  F1=60,  F2=60,  F3=60   →  H=60,   penalty=0.6, S=36   [建议换车]


================================================================
九、关键技术细节汇总
================================================================

【信号处理工具箱】
  - FFT (快速傅里叶变换)           → 频谱分析
  - Butterworth 带通/低通滤波       → 频带提取
  - Hilbert 变换                    → 包络提取
  - Cepstrum (倒谱)                 → 周期性冲击检测
  - 自相关 (Autocorrelation)       → 基频估计
  - 滑动窗口方差 (向量化)           → 平整度/稳定性评估
  - 圆形方差 (Circular Variance)   → 相位集中度评估
  - 中值滤波 (Median Filter)       → GPS 降噪
  - find_peaks                      → 峰值检测
  - 线性插值 (重采样+评分映射)       → 时间对齐+连续评分

【防御性编程】
  - 数据量不足 (<64 条加速度计) → 返回默认满分，不崩溃
  - 除零保护 (safe_div, eps=1e-6)
  - 采样率范围限制 (1000~96000Hz)
  - 踏频范围限制 (0.5~8Hz)
  - find_peaks 距离参数限幅 (防止 length/2 越界)
  - GPS 航向角 0°/360° 环绕处理
  - 滤波截止频率裁剪到 Nyquist 范围 [0.001, 0.999]
  - 空数组/空列表兼容

【GPS 与 IMU 融合】
  - F1: GPS 速度 → 轮频先验 (缩小 FFT 搜索范围，提升鲁棒性)
  - F3: GPS 航向角 → 直行段 ground truth (大幅提升检测精度)
  - 窗口选取: GPS 速度方差 → 匀速段偏好 (加权 5.0)
  - 无 GPS 时自动降级: F1 全范围扫描, F3 用 IMU 偏置估计

【窗口选取评分权重设计原理】
  az_var × 1.0   —— 路面平整度 (基础权重)
  gz_var × 10.0  —— 直行稳定性 (关键因子，权重最高)
  speed_var × 5.0 —— 匀速偏好 (辅助因子)

  设计逻辑: 直行+匀速+平路 = 检测条件最理想
           gz_var 权重最高是因为转弯时偏航角变化会严重干扰 F3 检测


================================================================
十、算法创新点总结
================================================================

1. 零训练数据: 全部基于经典信号处理，不依赖机器学习标注数据
2. 包络谱+Cepstrum 双通道: 从不同数学域独立验证，降低误报
3. 冲击相位一致性: 利用链条异响的时空锁定特性区分环境噪音
4. GPS-IMU 松耦合: 有 GPS 用 GPS 增强，无 GPS 自动降级
5. 智能窗口选取: 向量化扫描亿万候选窗口，自动定位最优分析段
6. 木桶效应评分: 调和平均+最小值惩罚，杜绝「以好遮坏」
